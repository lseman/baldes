Shared-master network models

pyBaldes documentation · Results

Use independent pricing networks when several route families contribute to the same master constraints. Network IDs identify fleets or families; they need not be consecutive. Arc IDs and vertex IDs are local to a network. Shared-row IDs are positions in NetworkProblem.rows, starting at zero.

One network or a collection

Use the same solve function for scalar and array inputs:

Python
from pybaldes import PricingArc, PricingNetwork, solve

network = PricingNetwork(
    id=7, vertices=3, multiplicity=(0, 1),
    arcs=(PricingArc(0, 1, -2), PricingArc(1, 2, 0)),
)
a = solve(network, stabilize=False)
b = solve([network], stabilize=False)
assert a.lp == b.lp == -2
assert a.oracle_calls == b.oracle_calls

Pass rows=rows with a scalar/array, or use NetworkProblem(rows, networks). The latter accepts a scalar network or an array and always stores a tuple. pricing_variables optionally registers original pricing-variable mappings; see the model compilation contract.

Build a complete model

Python
from pybaldes import (
    NetworkProblem, PricingArc, PricingNetwork, PricingResource, SharedRow,
)

problem = NetworkProblem(
    rows=[SharedRow("eq", 1.0)],
    networks=[PricingNetwork(
        id=19, vertices=3, multiplicity=(0.0, 1.0),
        arcs=[
            PricingArc(0, 1, 2.0, consumption=(1.0,), entries=((0, 1.0),)),
            PricingArc(1, 2, 1.0, consumption=(0.0,)),
        ],
        resources=[PricingResource(bounds=((0.0, 2.0),) * 3)],
    )],
)
root = problem.solve(stabilize=False)
assert root.status == "Optimal" and root.lp == 3.0
print(root.routes[0].network, root.routes[0].nodes)

NetworkRoute.coupled_values is an immutable tuple of paired descriptor/value pairs retained with the scalar resource_profile. Values describe the current selected physical dependent state, independently of objective normalization; they are not full control trajectories or standalone feasibility certificates.

The only covering route costs 3, contributes one unit to shared row 0, consumes one load unit, and uses one copy of network 19's allowed route multiplicity. problem.solve(**options) delegates to solve(problem, **options). Both require Clp.

Model reference

Type Fields and defaults
SharedRow sense, rhs; sense is "eq", "le", or "ge"
PricingResource kind="disposable", initial=None, bounds=None, time_windows=None
PricingArc tail, head, cost, consumption=(), bounds=(), entries=()
PricingNetwork id, vertices, multiplicity, arcs, resources=(), source=0, sink=None, route_entries=(), activity_entries=(), ng=None, coupled_resources=(), coupled_objective_coefficients=(), paired_waiting_base_resources=(), paired_machine_inputs=(), paired_machine_roots=(), paired_machine_terminal_bounds=(), elementary=False, route_domain=None, front_program_domain=False
NetworkProblem rows, scalar/array networks, optional pricing_variables

Scalar kind accepts "disposable" or "equality". Resource bounds has one (lower, upper) pair per vertex when supplied; initial overrides the source initial value. Optional windows are described in resources. PricingArc.consumption follows scalar coordinate order. Arc bounds entries are optional (lower, upper) pairs constraining head states. entries contains (shared_row_index, coefficient) pairs for that arc.

For a route p in network k, an additive shared-row coefficient is the sum of its arc entries plus route_entries once per route. Multiplicity (lower, upper) bounds the sum of route variables in that network. Shared coverage rows and fleet multiplicity are different constraints. sink=None selects the last vertex. ng supplies per-vertex neighborhoods; elementary=True selects an elementary network domain. coupled_resources accepts tagged descriptors.

paired_waiting_base_resources=((coupled_index, scalar_index), ...) opts a slope_paired resource into waiting windows derived from the corresponding scalar resource. Each physical arc's window intersects its head vertex bounds with the arc bounds; absent arc bounds use -1e12 and 1e12. Indices refer to coupled_resources and resources, respectively. Duplicate coupled indices, invalid indices, empty intersections, and scalar resources with multi-time windows are rejected. The equivalent CLI JSON field uses arrays of pairs, for example "paired_waiting_base_resources": [[0, 1]]. An omitted or empty field leaves the paired resource's existing waiting behavior unchanged.

paired_machine_inputs=((coupled_index, arc_inputs), ...) attaches exact prepared machine operands to a slope_paired resource using front_algebra. arc_inputs contains one mapping per physical arc in insertion order. Each mapping supplies finite tail_limit, head_limit, waiting_lower, waiting_upper, integer waiting_rate, and forward_mapping, inverse, sum_vector, dependent_lower, and dependent_upper functions. Encode each function as {"pairs": [[value, coordinate], [slope, end], ...]}. The machine decoder also accepts a zero-width two-pair vector and a three-pair vector with a zero-width first segment. The waiting limits must be ordered. Resource indices must be unique and each arc vector must match the graph's arc count. An arc may also include a backward mapping with tail_lower, tail_upper, forward_at_tail_lower, mapped_upper, and dependent (a prepared function in the same pairs format). These are the separate operands needed by the backward recurrence, which remains incomplete. These inputs invalidate prepared pricing state when changed. When front_program_domain is enabled, the incomplete machine path uses them and also requires paired_machine_roots=((coupled_index, {"pairs": [...]}), ...) with the separately prepared dependent root vector. The equivalent JSON field is an array of [coupled_index, arc_inputs] pairs. An omitted field defaults to empty. To initialize backward machine labels, supply paired_machine_terminal_bounds=((coupled_index, (lower, upper)), ...) with the prepared terminal base window. The associated arc operands must already be supplied in paired_machine_inputs.

coupled_objective_coefficients=((resource_index, coefficient), ...) sets graph-level costs using each descriptor's declared normalization. With Clp, negative source paired costs support both absolute and final-minus-initial normalization. A relative objective subtracts the global initial-front minimum, independently of the witness's initial coordinate. Each resource has one cost owner: omit its graph coefficient when an original pricing_variables entry binds that resource. Duplicate indices, unsupported descriptors and nonfinite coefficients are rejected by the common graph setter. Omitted resources keep coefficient one. The field works for one network and arrays of networks.

The Rust interface additionally supports independent master variables and imported-column domains. Those registrations are not fields in the CLI/Python network JSON schema. pricing_variables registers original pricing-variable identities; it does not add arbitrary static master variables. See the shared model guide and column imports for the Rust-only contracts.

An original variable can use accumulated_resource instead of arcs to bind the intrinsic charge of a custom/cumulative coupled descriptor. Its cost replaces the descriptor's unit objective coefficient; entries adds that intrinsic activity to shared rows. Reported activity remains independent of the objective coefficient. Accumulated registrations support continuous variables, integer registrations with complete exact-integer path proofs, and explicit original-variable boxes whose envelopes can be certified over the complete bounded graph relaxation. Direct network activity_entries use objects with resource, row and coefficient fields. See original variable compilation for the shared contract.

accumulated_resource also accepts cost-bearing paired descriptors (raw slopes or control points) with absolute_final_value normalization and a finite cost. Negative costs require a source-domain model and use maximum-control pricing. The reported value comes from the selected column, independently of the cost coefficient. For this paired binding, entries supports signed shared-row coefficients in source-domain models. integer=True is accepted when a program or complete control-domain proof establishes integral terminal activity for every control. Continuous ranges with integral endpoints are rejected. Verified original_variable_boxes enclose all controls, including nonminimum choices; they are envelopes, not new model restrictions. Automatic pricing covers finite physical paths and independently bounds alternative source controls. Incomplete coverage remains explicit. Machine-front integer activities/negative objectives and rows remain unsupported.

Model JSON

Python
from pathlib import Path
from pybaldes import NetworkProblem

text = problem.to_json(indent=2)
restored = NetworkProblem.from_json(text)
assert restored == problem
Path("model.json").write_text(text, encoding="utf-8")
restored = NetworkProblem.from_file("model.json")

The same model format is accepted by baldes solve model.json. JSON rejects non-finite numeric literals; an unlimited multiplicity upper bound uses null as described in the shared model contract. Synchronization definitions are solve options, not fields in NetworkProblem.to_json(); save them separately for reproducibility.

A schedule changes which networks are priced first; early improving columns do not establish that all networks have completed pricing. The solver coordinates the complete pricing checkpoint needed for bounds.

Example proximal configuration:

Python
root = problem.solve(
    network_pricing_schedule="promising-first",
    proximal={"bands": [{"half_width": 0.5, "penalty": 1.0}], "multi_point": True},
)

penalty=None selects a hard band. Use positive validated widths/penalties; see proximal pricing for the mathematical contract. Root and tree APIs have different option sets from routing solve; there is no master_solver keyword here.

Resume, branch, and add rows

A root result owns a NetworkNode snapshot. Child operations return new nodes and preserve their parent. Handles are bound to their creating Python thread.

Python
from pybaldes import NetworkRowCoefficients, SharedRow

root = problem.solve()
parent = root.snapshot
assert parent is not None
# Add an additive row requiring at least one route across the networks.
coefficients = tuple(
    NetworkRowCoefficients(n.id, (0.0,) * len(n.arcs), per_route=1.0)
    for n in problem.networks
)
child = parent.with_row(SharedRow("ge", 1.0), coefficients)
child_result = child.solve(stabilize=False)
assert parent.solve().lp == root.lp

NetworkRowCoefficients(network, arcs, per_route=0.0, activities=()) supplies one coefficient per physical arc and optional (coupled_descriptor, coefficient) activity terms. The constant is charged once per route. Deterministic activities and selected source paired values use the same with_row lifecycle, including dynamic=True. These terms apply to existing and future columns. An existing complete universe accepts a paired term only after an all-control invariance proof confirms that its retained coefficients remain valid.

parent.fractional_assignments(tolerance=1e-6) returns NetworkAssignment objects with shared_row, network, and value. A candidate can be branched:

Python
for candidate in parent.fractional_assignments():
    assigned = parent.branch_assignment(candidate.shared_row, candidate.network, True)
    excluded = parent.branch_assignment(candidate.shared_row, candidate.network, False)
    print(assigned.solve().status, excluded.solve().status)
    break

Use candidate IDs from the solved snapshot and supported original assignment rows. Arbitrary shared rows need not define assignment disjunctions. fix_route(route_index, quantity=1) fixes a route using the snapshot's route handle. quantity must be a positive Python integer at most 2**53; booleans and fractional values are rejected. Use a non-None route_index from that snapshot's routes, not an index into an unrelated result.

with_resource_group_branch(packing_row, resource, threshold, upper, members) accepts NetworkResourceGroupMember(network, arcs) objects. The original packing row must establish at most one occurrence. The operation has resource replay and row compatibility preconditions, including enumeration for some resource-load rows. See grouped branches for the shared boundary convention and restrictions.

Integer search

Python
from pybaldes import NetworkProblem

# Bundled example, run from the repository root.
triangle = NetworkProblem.from_file("examples/networks/triangle.json")
root = triangle.solve(stabilize=False)
integer = triangle.solve(tree=True, time_limit=30, node_limit=1000)
assert root.lp == 1.5
assert integer.incumbent == 2.0
print(integer.status, integer.bound, integer.open_nodes)

root.snapshot.solve(tree=True, ...) starts a tree from that node's inherited state. Automatic search supports its documented branching families and may return Incomplete when they do not resolve the model. A tree result has no resumable node snapshot. An incumbent remains distinct from a lower bound.

Enumeration and integer transfer

Keyword Default Meaning

enumeration_route_limit 10000 Candidate route budget across networks

Python
root = triangle.solve(enumerate=True)
for report in root.enumeration_reports:
    print(report.complete, report.routes, report.failure, report.coverage_cutoff)

Full transfer commits only when every enabled network completes. Unsupported resources, ambiguous replay, or exhausted limits leave normal pricing available and do not install a partial universe. A failed attempt may be retried by a later solve with different limits. NetworkNode.solve_enumerated_mip(time_limit=1.0, node_limit=100000, objective_cutoff=None) solves an available transferred copy and may return None when unprepared. HiGHS support is required for integer solving.

With tree=True, enumerated_mip=True, the solver can use full transfer or a cutoff-bounded improvement domain. Inspect each report's coverage_cutoff: None means full-domain coverage; a number restricts coverage to improvements below it. Failure to improve an arbitrary cutoff is not original-model infeasibility and does not supply a feasible incumbent. Independent certificates and numerical MIP bounds remain distinct. See the enumeration contract.

Synchronized optional service

SynchronizedService(id, resource, vehicles_required, reward, start, members) defines a job served by distinct vehicle copies at a common integer service start. Members are SynchronizedServiceMember(network, vertex) values. Service is optional and its reward is counted once in the master, so exclude that reward from route arc costs and remove ordinary unit-cover rows for this job.

Python
from pybaldes import SynchronizedService, SynchronizedServiceMember

fleets = NetworkProblem((), tuple(
    PricingNetwork(
        id=n, vertices=3, multiplicity=(0, 1),
        arcs=(PricingArc(0, 1, 0), PricingArc(1, 2, 0)),
        resources=(PricingResource(initial=0, bounds=((0, 0), window, (0, 100))),),
    ) for n, window in ((7, (0, 9)), (42, (5, 10)))
))
service = SynchronizedService(
    id=17, resource=0, vehicles_required=2, reward=1,
    start=(0, 10),
    members=(SynchronizedServiceMember(7, 1), SynchronizedServiceMember(42, 1)),
)
result = fleets.solve(tree=True, synchronized_services=(service,))
assert result.incumbent == -1
assert all(r.resource_profile[1][0] == 5 for r in result.routes)

The synchronized resource must be disposable with nonnegative consumption. Put service duration on outgoing arcs. Start bounds are inclusive integers in [-2**52, 2**52]; the unit determines the time grid. The synchronized axis is a graph scalar resource; separate coupled resources may coexist. Resource-load rows on the same axis are refreshed when synchronized start domains change. The routing registration accepts bounded walks without cuts; its automatic cut families require a hard vertex elementarity group on every interior vertex. That restriction belongs to routing cut hooks and is independent of network count. Root LP columns need not form a synchronized schedule; the tree validates the joint integer witness.

A snapshot's service definitions are immutable. Narrow a start domain with with_synchronized_start(id, lower, upper); parents remain reusable. Complete MIP is deferred while common start domains are non-singleton. The synchronization contract explains coverage equations and schedule validation.

Original-variable pricing envelopes can be passed to solve or a node solve:

Python
result = problem.solve(
    original_variable_boxes=({"network": 7, "id": 0, "lower": 0, "upper": 1},),
)

Each identity must occur in problem.pricing_variables. The bound must already follow from the pricing graph; an unproved envelope raises an error. These bounds guide pricing admission without adding a route restriction. Original variable costs remain separate during this calculation even if they cancel on shared physical arcs. See the compilation contract.

Explicit source choices can be retained for an existing route with node.with_route_controls(route_index, (PairedControl(resource, base), ...)). base contains the initial coordinate and one head coordinate per arc. The result is a new node; duplicate identities are reused. Controls need independent singleton source certificates, and complete/cutoff universes and machine-front model domains reject this operation. route.coupled_controls is an immutable tuple of PairedControl objects. Values and costs survive resume, fixing and tree solving; original-variable reporting reads the supplied selected value. Models without paired rows retain ordinary minimum-front pricing. Paired rows use the same master coordinator with bounded source-control generation, including reversed reduced weights and row-boundary proposals. Complete enumeration retains invariant terminal values or a certified attained endpoint that weakly improves both the objective and every row. Negative costs favor maxima, positive costs minima, and zero costs either direction, subject to all row signs and inequality senses. Equality rows, opposing requirements, identity-specific column caps, and uncertain/unattained bounds remain guarded. A new Gamma row may reuse invariant matching values or the same certified endpoints when they still favor the objective and every old/new row. Repeated terms are checked together; restrictive retained-column caps and fixed-copy certificates remain part of the proof. Opposing/equality rows requiring other controls cannot widen the projected universe. Negative model costs use the same bounded source-control optimizer; machine-front negative models remain unsupported.

node.optimize_route_control(route_index, resource, maximize=False, terminal=None, max_cells=4096, max_work=1_000_000, max_lp_iterations=10000, time_limit=1.0) generates a source control on one registered path. terminal=(lower, upper) restricts its physical dependent value. It returns an immutable ControlOptimization with control, dependent, work_used, lp_iterations, lower_bound, complete, maximize and cells.

Python
choice = node.optimize_route_control(route_index, 0, terminal=(4.0, 4.0))
if choice.control is not None:
    node = node.with_route_controls(route_index, (choice.control,))

Every returned control has an independent source certificate. complete=True means all regions were bounded/rejected and a feasible control was found, or all regions were proved empty. It does not assert a zero primal/dual gap. lower_bound applies to Gamma, or -Gamma when maximizing. An incomplete result can retain a useful feasible control; it cannot assert infeasibility. This is a fixed-path descriptor search, not a whole-model pricing certificate. Its limits are shared across LP regions. Machine-front models reject the source search.
