01 — Engine

Why BALDES?

A purpose-built pricing engine for vehicle routing. Bucket graphs accelerate dominance checks, bidirectional labeling doubles search throughput, and cutting planes close the gap — all orchestrated by a branch-cut-and-price core.

🗂️
Bucket Graph Labeling
Labels organized in buckets by vertex and resource intervals. N-dimensional Splay Trees enable efficient access — four-phase solving from fast estimation to exact dominance.
⚡
Parallel Bi-directional Pricing
Forward and backward search run in parallel with AVX-optimized n-dimensional dominance checks, cutting labeling time in half.
✂️
Cutting Planes
Limited-memory Subset Row Cuts (SRC) and Rounded Capacity Cuts (RCC) separate in parallel, tightening the LP relaxation between pricing rounds.
🌲
Multi-stage Branching
Pseudo-cost history → fractional proximity → LP relaxation evaluation. The branching policy adapts to the problem structure at each node.
🧬
Heuristic Warm Starts
Built-in Hybrid Genetic Search (HGS) provides high-quality initial solutions. Improvement heuristics (RIH) further refine incumbents during solve.
🐍
Python Bindings
Full Python interface via nanobind. Build instances, run pricing, and inspect results directly from Python notebooks or scripts.

03 — Algorithms

Four-phase pricing strategy

Bucket graphs transform the labeling problem. Each phase filters and tightens until the optimal path is isolated — no wasted computation.

01
Min cost per bucket
Filter the search space. Estimate lower bounds on arc costs using bucket minima — discard paths that can't improve the incumbent.
02
Relax dominance
Expand label retention. Relax dominance checks to keep promising but non-dominated labels that might become optimal after further extension.
03
Estimate bounds
Discard suboptimal. Refine bound estimates with tighter resource usage projections — prune buckets that cannot yield feasible solutions.
04
Exact dominance
Find the optimal path. Apply exact n-dimensional dominance on the surviving labels — the remaining path is provably optimal for the restricted master.
04 — Design

Built for research & production

Every architectural decision balances algorithmic correctness, memory efficiency, and extensibility over convenience magic.

01
Algorithm-first design
The bucket graph architecture mirrors the mathematical structure of the pricing problem — no abstractions leak the model.
02
Memory-conscious
Limited-memory SRC cuts, bounded bucket capacity, and in-place label management keep peak RAM predictable.
03
Solver-agnostic core
HiGHS, Gurobi, or the in-house interior-point solver — swap LP backends without touching the pricing engine.
04
Extensible via CMake
Toggle features at configure time — bucket fixing, sorted labels, unreachable dominance, RIH — no runtime overhead for what you don't enable.
